# Deploying the remaining production workflows

Run these migrations in Supabase SQL Editor in this order, once each:

1. `0003_secure_attendance.sql`
2. `0004_agent_replenishment_audit.sql`
3. Run `supabase/audits/rls_storage_audit.sql` and inspect that RLS is enabled, policies are least-privilege, and the attendance bucket is private.

The attendance migration creates a private `attendance-evidence` Storage bucket and the `attendance_events` table. It also adds the `submit_attendance_event` RPC. Check-in time is generated by Postgres. Store geofencing is evaluated on the server when verified latitude, longitude and a positive radius are present; otherwise the event is saved as pending manual review.

The agent/replenishment migration creates `agent_activity_logs`, `replenishment_reviews` and `inventory_movement_events`. Replenishment approvals are audit decisions only: they do not create purchase orders or change stock quantities.

## Deploy Supabase Edge Functions

From the repository root, with the Supabase CLI linked to the correct project:

```bash
supabase functions deploy create-workspace-user
supabase functions deploy send-daily-reports
```

Configure secrets in Supabase Edge Function secrets (never in Vite/browser variables):

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `RESEND_API_KEY`
- `REPORT_FROM_EMAIL` (must be a sender/domain verified with Resend)
- Optional `REPORT_RECIPIENT`

The service-role key must only exist in Edge Function secrets. The user provisioning function checks the caller's authenticated profile role before creating an Auth user and profile.

## Important operational prerequisites

- Enter verified store latitude, longitude and geofence radius before treating a check-in as geofence-verified. Blank coordinates deliberately produce pending review.
- Attendance photos are private. Employees can upload/read their own evidence; admins can read evidence. No public bucket URL is created.
- The report Edge Function sends two PDFs (sales/inventory and attendance) to the requested recipient. It requires a working Resend account and verified sender.
- The Employee Directory account creation form requires the `create-workspace-user` Edge Function to be deployed.
- Agent Runs shows real activity records. Sales imports, inventory batch receipts and attendance check-ins write logs. It does not imply autonomous agents are continuously running.
- Inventory movement events are an audit ledger; no stock quantity changes are inferred from an approval or log record.
- Browser camera and GPS permissions require HTTPS or localhost.
